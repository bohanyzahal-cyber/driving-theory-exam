# נהלי תפעול ופריסה

> קרא לפני **כל** פריסה. רוב התקלות ההיסטוריות במערכת הזו לא היו באגים בקוד אלא בפריסה שלא הושלמה.

## 0. הכלל שחייבים להפנים

**שלושה יעדי פריסה נפרדים. `git push` מעדכן רק אחד מהם.**

| יעד | מה נפרס | איך | מי יכול |
|---|---|---|---|
| GitHub Pages | קבצי HTML/JS/PWA | `git push` לענף `master` | אוטומטי |
| Google Apps Script | `external_exam_apps_script.js` | הדבקה ידנית בעורך | רק בעל החשבון |
| Cloudflare Workers | `cloudflare-workers/*.js` | `npx wrangler deploy` | בעל חשבון Cloudflare |

שינוי בקובץ ה-Apps Script שנדחף לגיט **אינו באוויר**. זה תפס אנשים שוב ושוב.

## 1. פריסת לקוח (GitHub Pages)

### מתי מותר לדחוף

| קובץ | מתי | למה |
|---|---|---|
| `examinee.html` | **רק כשאין נבחנים ממתינים או במבחן** | הדף מרענן את עצמו תוך ~2 דקות מהפריסה |
| `student.html` | עדיף בשעה שקטה | אותו מנגנון רענון שקט |
| `examiner.html` | כל זמן | מציג באנר עם שהות 60 שניות |
| `teacher.html` | כל זמן | אותו הדבר |

מנגנון הרענון: כל דף בודק את ה-ETag של עצמו כל 2 דקות ומרענן כשזוהה שינוי. ב-`examinee.html` הרענון חסום כשיש מבחן פעיל **או נבחן רשום** (המגן הורחב 28/07/2026); ב-`student.html` הבדיקה צרה יותר.

**תמיד לשאול את המשתמש אם יש בחינות לפני דחיפת דף שנוגע לנבחנים.**

### הנוהל

```bash
cd standalone_exam
git status
git add <files>
git commit
git push origin master
```

הענף הוא **`master`** (לא `main`), והרימוט הוא `driving-theory-exam` — לא מאגר השורש.

### אימות שהפריסה עלתה

אל תסתמך על "נראה תקין בדפדפן" — יש שכבת service worker ומטמון HTTP של 600 שניות שיכולים להטעות.

```bash
gh api repos/bohanyzahal-cyber/driving-theory-exam/pages/builds/latest --jq '.status'
```

ואז שליפה טרייה עם עוקף מטמון, מול סמן ייחודי מהשינוי:

```bash
curl -s -H 'Cache-Control: no-cache' "https://bohanyzahal-cyber.github.io/driving-theory-exam/examiner.html?cb=$(date +%s)" | grep -c "<סמן ייחודי>"
```

בחר סמן ב-ASCII (שם משתנה, לא טקסט עברי) — קונסולת Windows הופכת עברית ל-`?????`.

בנייה נמשכת בדרך כלל 30-90 שניות. לפעמים ה-API עדיין מדווח `building` בזמן שהתוכן כבר מוגש — **השליפה בפועל היא הקובעת**.

## 2. פריסת שרת (Google Apps Script)

### הנוהל

1. **בדוק תחביר לפני הכל:**
   ```bash
   node --check external_exam_apps_script.js
   ```
   שגיאת תחביר בהדבקה משביתה את **כל** המערכת.
2. פתח את פרויקט ה-Apps Script המקושר לגיליון.
3. החלף את **כל** תוכן הקובץ (הדבקה מלאה — כך זה נעשה תמיד כאן).
4. `Deploy` → `Manage deployments` → עיפרון → `Version: New version` → `Deploy`.

**קריטי:** בלי בחירת `New version` הקוד נשמר אבל הכתובת הציבורית ממשיכה להגיש את הגרסה הישנה. תקלה שקטה ומבלבלת.

### תופעת הלוואי של ההדבקה המלאה

הדבקה מלאה פורסת **את כל מה שהצטבר בקובץ**, לא רק את השינוי האחרון. אם עברו שבועות מההדבקה הקודמת, בדוק מה נכנס:

```bash
git log --oneline -20 -- external_exam_apps_script.js
```

ואמור למשתמש מה עוד עולה איתו. אחרת שינוי התנהגות בלתי מוסבר ייזקף לשינוי האחרון.

### אימות שהשרת חי

```bash
curl -s -L --max-time 45 "<EXEC_URL>?action=getSessionInfo&sessionCode=ZZZZZZ&origin=examinee-app"
```

תשובה תקינה: `{"status":"error","message":"קוד סשן לא תקין"}` — כלומר ה-handler רץ.

- **בלי** `&origin=examinee-app` תקבל `{"status":"error","message":"Missing origin"}`. זו התנהגות **תקינה** של ה-allowlist, לא תקלה.
- זמן תגובה תקין: כ-2-9 שניות. עשרות שניות = רעב לחוטי ביצוע, ראה §5.

ה-`EXEC_URL` נמצא בתוך כל דף לקוח כ-`API_URL`.

### ⚠️ שתי כתובות API

ששת הדפים (`examiner`, `examinee`, `teacher`, `student`, `admin`, `exam`) מצביעים על deployment אחד. **`report.html` מצביע על deployment אחר.** אם אתה מחליף כתובת API — בדוק את שניהם. לא אומת אם ההפרדה מכוונת או שריד היסטורי; **לברר לפני נגיעה**.

## 3. פריסת Cloudflare Workers

```bash
cd cloudflare-workers
npx wrangler deploy
```

**אל תפרוס דרך דשבורד Cloudflare.** תועד שם כישלון כפול: הדבקת קוד Modules לעורך מסוג Service-Worker נכשלת בשקט, ו-Deploy מהעורך מחזיר 403. `wrangler` עובד.

Workers פעילים: קישורי דו"חות (`steep-night-dd06`, עם KV), TTS עברית (`hebrew-tts`), פרוקסי תמונות.

אימות: `curl https://steep-night-dd06.bohanyzahal.workers.dev/` — אמור להחזיר `"links":"permanent"`.

Secrets שורדים פריסה. חיבור ה-KV נשמר כי הוא ב-`wrangler.toml`.

## 4. עדכון בנק השאלות

**בנק השאלות אינו במאגר.** הוא חי בתיקיית Drive פרטית, מוגדרת ב-ScriptProperty `QUESTIONS_DRIVE_FOLDER_ID`, קובץ JSON לכל שפה.

עריכת JSON מקומי לא עושה **כלום**. הנוהל:

1. ערוך את ה-JSON של השפה.
2. העלה ל-Drive והחלף את הקובץ.
3. הרץ בעורך ה-Apps Script: `emergencyClearAndRefreshCache()`.
4. אמת מול ה-API החי ששאלה שהוסרה כבר לא מוגשת.

**חובה לשמור על התשובה הנכונה באותו אינדקס** — שינוי סדר תשובות שובר ניקוד למפרע.

יש טיפול נפרד לכל שפה. שינוי ששודרג בעברית לא נכנס לרוסית עד שגם היא הועלתה.

## 5. חירום

### כל הדפים "לא מתקשרים"

בדוק **קודם** את זמן התגובה של ה-API (§2). עשרות שניות או 0 = רעב לחוטי ביצוע ב-Apps Script, לא באג בלקוח.

שתי תבניות מתועדות:
- **~13:00, כ-15 דקות, נפתר מעצמו** — פקיעת מטמון השאלות וגל תחילת-מבחנים על מטמון קר.
- **9:00-11:00** — סריקות כבדות בדשבורד הבוחן.

שתיהן טופלו (נעילת stampede + אינדוקס), אבל התסמין חוזר → בדוק שטריגר החימום חי.

### שאלות לא נטענות / מטמון מורעל

`emergencyClearAndRefreshCache()` בעורך ה-Apps Script. עברית נשברת ראשונה (הקובץ הגדול ביותר).

### לקוח שבור — החזרה לאחור

```bash
cd standalone_exam
git revert <commit> --no-edit
git push origin master
```

**החזרת שרת לאחור דורשת הדבקה ידנית של גרסה קודמת.** אין דרך מהירה. לכן שרת נפרס ראשון בשינויים אדיטיביים — שרת חדש מול לקוח ישן הוא no-op בטוח.

### תוצאה שנעלמה

תוצאות נשמרות מקומית עד לאישור השרת, ונשלחות מחדש בטעינת הדף. לפני שמכריזים על אובדן — בדוק `localStorage` במכשיר, וחפש שורות `פסול`/`טיימאאוט` בגיליון שהוחלפו על-ידי הגשה מאוחרת.

## 6. סדר פריסה בשינוי מרובה-צדדים

1. **שרת ראשון** — אם השינוי אדיטיבי (שדות חדשים בתשובה, פרמטרים אופציונליים). לקוח ישן מתעלם.
2. **לקוח ראשון** — אם השרת נעשה מחמיר יותר (דרישת פרמטר חדש). אחרת הלקוח הישן נשבר ברגע הפריסה.

טעות בסדר כאן השביתה התחברות בעבר. אם לא ברור לאיזה סוג השינוי שייך — הנח שהוא מהסוג השני.
