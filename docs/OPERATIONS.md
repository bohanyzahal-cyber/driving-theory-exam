## 2. פריסת שרת (Google Apps Script)

### הנוהל

0. **הקובץ מיוצר.** מקור השרת הוא `server/src/*.js` (סדר ב-`server/BUILD_ORDER.json`). לעולם לא עורכים את `external_exam_apps_script.js` ישירות:
   ```bash
   node tools/build.js
   ```
   בונה את הבנק הסטטי (`bank/`), את `deployment/question_index.json`, מרכיב את קובץ השרת (כולל `node --check`), ומעדכן `version.json` ושמות המטמון ב-service workers. `node tools/build_server.js --check` אומר אם הקובץ המחויב בגיט מעודכן.
1. **בדיקות:** `node tools/test.js` — כל החבילות חייבות להיות ירוקות.
2. פתח את פרויקט ה-Apps Script המקושר לגיליון.
3. החלף את **כל** תוכן הקובץ (הדבקה מלאה — כך זה נעשה תמיד כאן). `answer_key.gs` הוא קובץ נפרד בעורך ומודבק רק כשהמפתח משתנה.
4. `Deploy` → `Manage deployments` → עיפרון → `Version: New version` → `Deploy`.

**קריטי:** בלי בחירת `New version` הקוד נשמר אבל הכתובת הציבורית ממשיכה להגיש את הגרסה הישנה. תקלה שקטה ומבלבלת. (טריגרים, לעומת זאת, רצים על הקוד החדש מיד עם השמירה.)

### תופעת הלוואי של ההדבקה המלאה

הדבקה מלאה פורסת **את כל מה שהצטבר בקובץ**, לא רק את השינוי האחרון. אם עברו שבועות מההדבקה הקודמת, בדוק מה נכנס:

```bash
git log --oneline -20 -- external_exam_apps_script.js
```

ואמור למשתמש מה עוד עולה איתו. אחרת שינוי התנהגות בלתי מוסבר ייזקף לשינוי האחרון.

### אימות שהשרת חי

```bash
curl -s -L --max-time 45 "<EXEC_URL>?action=getSessionInfo&sessionCode=ZZZZZZ&origin=examinee-app"
```

תשובה תקינה: `{"status":"error","message":"קוד סשן לא תקין"}` — כלומר ה-handler רץ.

- **בלי** `&origin=examinee-app` תקבל `{"status":"error","message":"Missing origin"}`. זו התנהגות **תקינה** של ה-allowlist, לא תקלה.
- זמן תגובה תקין: כ-2-9 שניות. עשרות שניות = רעב לחוטי ביצוע, ראה §5.

ה-`EXEC_URL` נמצא בתוך כל דף לקוח כ-`API_URL`.

### ⚠️ שתי כתובות API

ששת הדפים (`examiner`, `examinee`, `teacher`, `student`, `admin`, `exam`) מצביעים על deployment אחד. **`report.html` מצביע על deployment אחר.** אם אתה מחליף כתובת API — בדוק את שניהם. לא אומת אם ההפרדה מכוונת או שריד היסטורי; **לברר לפני נגיעה**.

## 3. פריסת Cloudflare Workers

```bash
cd cloudflare-workers/session-gateway     # סקר הנבחנים + בנק השאלות הפרטי (assets/)
node ../../tools/build_bank.js            # מייצר assets/ מהדאמפים (לא בגיט) — חובה לפני כל deploy
npx wrangler deploy                       # מעלה את הקוד וגם את 1,700 קבצי הבנק
```
(ה-Worker של קישורי הדו"חות: `cd cloudflare-workers && npx wrangler deploy`.)

**אל תפרוס דרך דשבורד Cloudflare.** תועד שם כישלון כפול: הדבקת קוד Modules לעורך מסוג Service-Worker נכשלת בשקט, ו-Deploy מהעורך מחזיר 403. `wrangler` עובד.

Workers פעילים: `session-gateway` (סקר הנבחנים + הבנק, `wrangler.jsonc` עם `assets`), קישורי דו"חות (`steep-night-dd06`, עם KV), TTS עברית (`hebrew-tts`), פרוקסי תמונות.

אימות `session-gateway`: `curl -s https://session-gateway.bohanyzahal.workers.dev/` מחזיר `bank` לא ריק; `…/v1/bank?grant=bogus` → 403; `…/bank/he.json` → 404 (הבנק אינו נגיש ישירות).

אימות: `curl https://steep-night-dd06.bohanyzahal.workers.dev/` — אמור להחזיר `"links":"permanent"`.

Secrets שורדים פריסה. חיבור ה-KV נשמר כי הוא ב-`wrangler.toml`.

## 4. עדכון בנק השאלות

**מאז 21/09/2026 בערב בנק השאלות פרטי ומוגש מה-Worker:** הטקסטים (בלי התשובות הנכונות) יושבים ב-`cloudflare-workers/session-gateway/assets/` (לא בגיט; מיוצרים מ-`deployment/generated/questions_<lang>.json`, המקור, לא בגיט, 25MB) ומוגשים על ידי ה-Worker רק לפי אישור חתום: נבחן/תלמיד מקבלים בדיוק את השאלות שהונפקו להם (`startExam`/`startPractice` → `bank.grant`), בוחן מקבל אישור בוחן (`bankGrant`) לחיפוש ולטבלת "שאלות שגויות". השרת מחזיק רק `QUESTION_INDEX` (נושא לכל דרגה + זמינות לפי שפה, מוזרק לקובץ השרת בבנייה) ואת מפתח התשובות `deployment/answer_key.gs` (קובץ נפרד בעורך, לא בגיט). אין Drive, אין מטמון שאלות, אין חימום, ואין בנק ב-Pages. פרטים: `DESIGN_2026-09-21.md` §11.

הנוהל לשינוי שאלה/תרגום:

1. ערוך את ה-JSON של השפה ב-`deployment/generated/`. **התשובה הנכונה חייבת להישאר באותו אינדקס** — אחרת `answer_key.gs` צריך להתעדכן באותו קומיט (`deployment/generate_answer_key.js`).
2. `node tools/build.js && node tools/test.js` — `bank_invariants` מוודא שלכל שאלה בכל שפה יש מפתח בטווח, שאין תמונה חסרה, שהאינדקס תואם לבנק ושלכל מזהה יש קובץ `q/<id>.json`.
3. `cd cloudflare-workers/session-gateway && npx wrangler deploy` — מעלה את ה-assets החדשים. הלקוח מקבל תמיד את הגרסה שב-Worker (אין מטמון בדפדפן ל-`/v1/bank`).
4. אם השתנה `QUESTION_INDEX` (שאלה נוספה/הוסרה/החליפה דרגה) — גם הדבקת קובץ השרת + גרסה חדשה. אם השתנה המפתח — גם הדבקת `answer_key.gs`. שינוי טקסט בלבד = Worker בלבד.
5. אימות: `curl -s https://session-gateway.bohanyzahal.workers.dev/` מציג `bank` = ה-build החדש (מ-`assets/manifest.json`); `health` מציג `indexIds`.

### כל הדפים "לא מתקשרים"

בדוק **קודם** את זמן התגובה של ה-API (§2). עשרות שניות או 0 = רעב לחוטי ביצוע ב-Apps Script, לא באג בלקוח.

שתי תבניות מתועדות:
- **~13:00, כ-15 דקות, נפתר מעצמו** — פקיעת מטמון השאלות וגל תחילת-מבחנים על מטמון קר.
- **9:00-11:00** — סריקות כבדות בדשבורד הבוחן.

שתיהן טופלו (מאז 22/09/2026 אין מטמון שאלות ואין חימום; לוח הבוחן ממודד ל-3 קריאות). אם התסמין חוזר — גיליון הווטשדוג קודם (§5, בוקר בחינות).

### שאלות לא נטענות

אין יותר מטמון שאלות בשרת ואין בנק ב-Pages. שלושה מצבים:

- **`bank_not_configured` בהתחלת מבחן** — חסר `GATEWAY_KEY` או `GATEWAY_URL` ב-Script Properties (`health&deep=1` מציג `gateway:{url,key}`). להשלים את המאפיינים; אין צורך בפריסה.
- **"לא הצלחנו לטעון את השאלות"** (הדף מנסה שוב לבד) — ה-Worker לא עונה או מחזיר 403/503: `curl -s https://session-gateway.bohanyzahal.workers.dev/` חייב להחזיר `bank` לא ריק. `bank` ריק = ה-assets לא הועלו (`node tools/build_bank.js` ואז `npx wrangler deploy`). 403 על אישור אמיתי = `GATEWAY_KEY` שונה בין ה-Worker (`wrangler secret`) לשרת (Property) — לקבוע את אותו ערך בשניהם.
- **"שאלה לא זמינה"** על שאלה בודדת — מזהה שקיים באינדקס אבל לא ב-assets: הבנייה וה-Worker לא מאותו build. `node tools/build.js` ואז `npx wrangler deploy` וגם הדבקת השרת.

התחלת מבחן נכשלת עם `bank_unavailable` רק כשהאינדקס בשרת ריק — כלומר הודבק קובץ שרת בלי הזרקת האינדקס (לבנות מחדש עם `node tools/build.js`).

### ה-Worker (session-gateway) לא זמין

**מאז 21/09 בערב ה-Worker הוא תלות קשה של התחלת מבחן** (הטקסטים מגיעים רק ממנו) — כמו ש-Drive היה עד r30. הסקר עצמו נופל לבד לסקר ישיר מול Apps Script אחרי 3 כשלים של ה-Worker; כדי לכבות רק את הסקר המאוחד בלי לגעת בטקסטים: Script Property `GATEWAY_POLL_OFF` = `1` (דף הנבחן קורא זאת ב-`getSessionInfo` בכל כניסת קוד סשן). **למחוק את `GATEWAY_URL` = אין טקסטים = אין מבחנים** — זה כבר לא מתג כיבוי אלא חלק מחזרה מלאה לאחור (`DEPLOY_2026-09-22.md` §8: גרסת Apps Script קודמת + לקוח r24 ב-Pages, שמקבל שאלות מהשרת). סטטוס Cloudflare: https://www.cloudflarestatus.com/.

### גיליון אבחון: שורות SLOW שלא הופיעו

מאז r22 (19/09/2026) שורת SLOW נכתבת לגיליון `אבחון` רק כל עוד הכתיבה עצמה בריאה: כתיבה שנכשלה או שלקחה יותר מ־2 שניות פותחת "מפסק" ל־5 דקות, ובזמן הזה השורות נחנות ב־ScriptProperties במקום להוסיף כתיבות למסמך שכבר תקוע (ב־17/09 כתיבת האבחון עצמה נתקעה 93 שניות; ב־16/09 לפחות שבע שורות של הרצות ארוכות אבדו). השורות החנויות נכתבות לגיליון בבדיקה השעתית (`ensureQuestionCachesWarm`), או מיד בהרצת `flushDiagnostics` מעורך הסקריפט. אם בבוקר בחינות הגיליון נראה ריק בזמן שהלוחות איטיים, להריץ `flushDiagnostics` לפני שמסיקים "לא היה כלום". הסימונים החדשים בעמודת ההערות: `ss:open` (פתיחת המסמך), `auth:token` (קריאת גיליון הבוחנים לפני המטפל), `tail:small/n` / `tail:1000/n` / `tail:full/n` (איזו קריאה בוצעה בפועל).

### בוקר בחינות — נוהל תפעולי (מהבדיקה של 18/09/2026)

1. **המקום הראשון להסתכל בו כשמשהו איטי הוא גיליון הווטשדוג** (`tools/exam_watchdog.gs`, סקריפט נפרד שמודד כל דקה 07:00–13:00): עמודת `verdict` אומרת `our-document` (המסמך שלנו נתקע), `dispatch`/`google/account` (גוגל), או `ok` בזמן שהבוחנים מתלוננים (הבעיה בלקוח/ברשת). התקנה חד-פעמית מתוארת בראש הקובץ.
2. **אישורים מדורגים** — לאשר כ-5 נבחנים כל 2 דקות ולא כיתה שלמה בבת אחת. גל של 43 רישומי מבחן בדקה (17/09, 09:21) הוא הכתיבה הכבדה ביותר על המסמך, ובדיוק בדקות האלה נתקעו הקריאות.
3. **מורים לא פותחים "פרטי כיתה" בין 09:00 ל-11:00 בימי בחינות** — כל פתיחה היא קריאה מלאה של 107 אלף שורות מאותו מסמך. זה מגבר, לא הסיבה, אבל מגבר שאפשר לכבות בטלפון אחד.
4. **באנר "השרת עמוס / משיב בשגיאה" בלוח הבוחן = לא לרענן ולא להתחבר מחדש.** הדף ממשיך לנסות לבד כל 30–60 שניות. רענונים והתחברויות בו-זמנית מכל הארץ הם שיצרו ב-16/09 את הפרצים של 200+ בקשות בדקה.
5. **גיליון אבחון ריק בזמן איטיות ≠ "לא היה כלום"** — להריץ `flushDiagnostics` מהעורך (ראו למעלה).
6. אחרי הבוקר: לקרוא את עמודת ההערות באבחון — `ss:open`, `auth:token`, `tail:full` אומרים איפה עברו השניות שלפני המטפל.

## 9. הפרדת נתוני התרגול והמורים לגיליון נפרד (r24, 19/09/2026)

**למה:** המסמך הוא יחידת התחרות. "פרטי כיתה" של מורה = קריאה מלאה של 107 אלף שורות מאותו מסמך שסקרי הבחינה קוראים וכותבים אליו, וערב תרגול לבדו הגיע לסף הדחייה של גוגל (16/09 19:46). שבעת גיליונות התרגול/המורים (`תוצאות תרגול`, `כיתות`, `תלמידי כיתות`, `מורים`, `התקדמות תלמידים`, `כיתות שנמחקו`, `חיזוי סיכון`) עוברים לגיליון Google נפרד. הקוד מנתב לפי שם הגיליון דרך ה-Script Property `PRACTICE_SPREADSHEET_ID`; כל עוד הוא לא מוגדר, הכול ממשיך לעבוד מהגיליון הישן.

**הנוהל, בסדר הזה:**

1. להדביק את קובץ השרת בעורך ולשמור.
2. להריץ מהעורך `practiceMigrationPreflight` (קריאה בלבד). בפעם הראשונה גוגל תבקש הרשאה חדשה — גישה מלאה לגיליונות (בגלל `openById`). לאשר. הדוח חייב להכיל "no formulas reference sheets across the practice/exam boundary". אם מופיעות נוסחאות שחוצות את הגבול — לעצור ולטפל בהן קודם.
3. "פריסה ← ניהול פריסות ← עריכה ← גרסה חדשה". מרגע זה הגרסה החיה יודעת לקרוא את ה-Property, אבל עדיין קוראת מהגיליון הישן.
4. **בשעה שקטה (ערב, שבת, לא ביום בחינות):** להריץ `migratePracticeSpreadsheet`. ההעתקה נעשית בנתחים של 4,000 שורות עם תקציב של 4.5 דקות לריצה (העתקת גיליון בפקודה אחת נכשלה על 109 אלף השורות: "Unable to load document"). ריצה שנגמר לה הזמן מסתיימת ב-`NOT cut over yet — run again`: להריץ שוב, היא ממשיכה מהשורה שבה עצרה. מהריצה הראשונה ועד ה-`CUT OVER` כתיבות תרגול נענות ב"מערכת התרגול בתחזוקה — נסה שוב בעוד דקה" (קריאות ממשיכות). היומן של הריצה האחרונה מסתיים ב-`CUT OVER` ובכתובת הגיליון החדש.
5. מיד אחר כך: `verifyPracticeMigration` — כל שורה `ok` ובסוף `ALL OK`.
6. אחרי יום של עבודה רגילה: `retirePracticeSheetsFromExamSpreadsheet` משנה את שמות העותקים הישנים ל-`_migrated_…`. שבוע אחר כך למחוק אותם ידנית מהגיליון הישן — **רק אז** מסמך הבחינות באמת מתכווץ.
7. חזרה לאחור בכל שלב: `rollbackPracticeSpreadsheet` מחזיר את הניתוב לגיליון הישן ומשחזר שמות. שורות שנכתבו לגיליון החדש אחרי המעבר לא מועתקות חזרה.

**מה משתנה למורים ולתלמידים:** כלום. אותה כתובת, אותם דפים. הגיליון החדש נמצא ב-Drive של אותו חשבון; אם מישהו קורא את `תוצאות תרגול` ישירות בגיליון, לתת לו את הכתובת החדשה מהיומן.
