# מודל הנתונים — Google Sheets

בסיס הנתונים של המערכת הוא גיליון Google Sheets אחד עם 14 לשוניות. אין schema ואין מיגרציות — **מיקום העמודה הוא החוזה**.

---

## 0. שלושה כללים לפני שנוגעים

### כלל 1 — קריאה מ-0, כתיבה מ-1

```js
var audio = data[i][9];                    // קריאה: מערך, אינדקס 0
sheet.getRange(i + 1, 10).setValue('on');  // כתיבה: getRange, אינדקס 1
```

**אותה עמודה, שני מספרים.** זה מקור הבאגים מספר 1 בקוד הזה. תמיד ודא מול הטבלאות למטה.

### כלל 2 — אסור להזיז עמודות

הקוד לא קורא לפי שם כותרת אלא לפי מספר. הוספת עמודה באמצע, מיון ידני של הגיליון, או מחיקת עמודה "מיותרת" — כל אחד מאלה שובר את המערכת בשקט. **עמודה חדשה נוספת רק בסוף.**

### כלל 3 — `SHEET_HEADERS` אינו מקור אמת

הקבוע בראש `external_exam_apps_script.js` הוא **תבנית ליצירת גיליון חדש**, ולא תיאור המצב בפועל. עמודות שנוספו אחרי היצירה הראשונית לא בהכרח נכנסו אליו. דוגמה מאומתת: `ממתינים` מתועד עם 15 עמודות, אבל הקוד כותב עד עמודה 19.

הטבלאות במסמך הזה משקפות את מה שהקוד **באמת** קורא וכותב.

### מכונת המצבים (עמודה F)

```
waiting ──approve──> approved ──start──> in_exam ──submit──> completed
   │                    │                    │
   │                    │                    ├──anti-cheat──> disqualified
   │                    │                                          │
   │                    │                        ┌──overturn───────┤
   │                    │                        ▼                 ▼
   │                    │                    in_exam        dq_confirmed
   ├──reject──> rejected
   └──cancel──> cancelled
```

**עקרונות שאסור לשבור:**
- `disqualified` = פסילה שממתינה להכרעת בוחן. הרשמה מחדש **חסומה** במצב הזה (אחרת נוצרות שתי שורות ואותו נבחן מופיע פעמיים ב"במבחן כרגע").
- ביטול פסילה חייב לטפל גם ב-`disqualified` וגם ב-`dq_confirmed`.
- `rejected` מדולג בבדיקת האישור בכוונה — ראה `KNOWN_ISSUES.md`.
- הקריאה תמיד **מהשורה האחרונה אחורה**, כי אותה ת.ז. יכולה להופיע כמה פעמים (ניסיון חוזר).

## 4. שאר הגיליונות

| גיליון | תפקיד | הערה |
|---|---|---|
| `בוחנים` | משתמשי בוחן | סיסמה, תפקיד, טוקן, נעילה אחרי כשלונות, אתרים מנוהלים |
| `מורים` | משתמשי מורה | מבנה דומה |
| `אתרים` | בסיסים/אתרים | + כיתות |
| `כיתות` | כיתות לימוד | קוד כיתה, מורה, דרגה |
| `כיתות שנמחקו` | ארכיון | מחיקת כיתה משאירה תוצאות יתומות; הארכיון משחזר את שם המורה. **רק מחיקות עתידיות מתועדות** |
| `תלמידי כיתות` | שיוך תלמיד לכיתה | |

| `הארכות זמן` | ביקורת הארכות באמצע מבחן | סיבה מתועדת חובה |
| `חיזוי סיכון` | פלט ה-batch הלילי | נבנה מחדש, לא מקור אמת |

## 6. הוספת עמודה — הנוהל

1. הוסף **בסוף בלבד**.
2. קרא הגנתית: `(row.length > N) ? row[N] : ''`.
3. עדכן את `SHEET_HEADERS` (לגיליונות חדשים) **וגם** את המסמך הזה.
4. זכור שהעמודה ריקה בכל השורות ההיסטוריות — אל תניח ערך.
5. אם היא צריכה לזרום לדו"חות — עדכן גם את מסלולי ההעתקה ל`תוצאות`.
